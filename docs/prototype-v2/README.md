# TUBA 全功能前端原型 v2

设计日期：2026-10-03。以当前功能契约和目标架构为依据，独立重建信息架构、视觉语言和主要操作流程。

## 查看与评审

本机预览：<http://127.0.0.1:8766/#/overview>。

直接打开 `index.html` 也可使用；无需 npm 安装或构建。重新启动预览：

```powershell
python -m http.server 8766 --bind 127.0.0.1 --directory C:\code\tuba\docs\prototype-v2
```

顶栏可以切换演示角色、工作空间、时间标签和页面状态。页面搜索可以直达详情页。管理操作请选择“平台管理员”；租户管理员没有独立发布权限。

所有数据均为合成数据，不连接 API、身份服务或部署环境。页面刷新清空本地模拟状态。列表详情使用代表性样例；时间和工作空间是范围控件的交互演示，不执行真实数据查询。查询执行显示示例结果，不包含 SPL 引擎。普通配置表单展示设计流程，并记录本地审计；完整字段和校验规则在实施时按契约补齐。截图中的运行指标、容量批准、备份目标及恢复时长不表示真实环境状态。

## 设计方向

产品定位为可解释行为分析与调查工作台。页面优先回答：发生了什么、影响谁、依据是什么、下一步做什么。

- 深蓝绿色导航建立稳定工作区，浅色内容面板承载长时间阅读。
- 青绿色用于操作和选中；红色表示高风险或失败，琥珀色表示待确认和警告。颜色必须配合文字。
- 总览只呈现行动优先级、风险、质量和新鲜度，不堆叠所有技术指标。
- 列表负责筛选排序；详情负责解释和操作；抽屉用于短证据查看；分步表单用于范围、生效条件和确认。
- 主页面显示业务语义，版本、checkpoint、哈希等实现依据放在上下文、血缘或管理详情中。
- 原文、敏感字段、管理权限和发布授权分别设计，不因“管理员”标签隐式放宽。
- 面向桌面调查工作；小屏转为单列布局，数据表保留横向滚动。

## 建议评审顺序

1. **调查闭环**：总览 → 异常详情 → 证据抽屉 → 实体画像 → 建案 → 案件分派 → 处置记录 → 证据快照 → 反馈。
2. **数据接入**：来源列表 → 新增来源三步表单 → 来源状态 → Agent 绑定 → 配置期望/生效 → 来源缺口。
3. **质量治理**：质量 → 语义隔离 → 失败字段 → 修复发布 → 受控回放 → 逐段对账 → 发布激活。
4. **分析运营**：特征/规则 → 样例评估 → 基线冷启动/训练 → 反馈评估 → 不可变新版本 → 发布评审。
5. **平台治理**：任务尝试/取消 → 运行容量 → 备份恢复 → 访问控制 → 审计。

## 分步操作与门禁

7 个三步表单：新增来源、回放、训练、导出、组件升级、恢复演练、发布激活。12 个管理表单：案件分派、自动建案、来源停用/上下文、Agent 绑定/准入、过滤启用/回滚、发布生命周期、模型生命周期、成员有效性、服务身份、发布授权。

重要的实现约束已经体现在原型信息中：

- 原文与敏感字段分开授权；下载再次授权，导出有时间、行数、体积和使用次数边界。
- 案件更新带对象 version；冲突保留编辑内容，展示服务端差异后重试。
- 自动建案默认关闭，finding 业务键保证幂等；人工建案和证据快照独立可追溯。
- 来源读取位置、Kafka offset、Raw receipt 和索引时间分别显示，不能合并成一个“正常”。
- Agent 管理离线不意味着采集停止；停用/恢复处理全部绑定来源 ACL，部分失败不可显示成功。
- shadow 过滤不丢弃事件；正式过滤区分源端和平台端，展示保护事件与各段计数。
- 统计训练门槛与事件保留独立，cold_start 不输出伪造统计评分。
- 发布按不可变资产、校验、暂存、激活、退役设计；生产代次唯一，回放不能直接进入生产风险。
- 回放对账显示输入 = 成功 + 隔离，并检查 checkpoint、outbox、lag、新鲜度和回滚资源。
- 备份清单明确跨系统非原子快照；未配置异机目标时不能显示已保障的整机损失 RPO/RTO。
- 通知端未配置显示仅本地告警，不能把界面告警当成已送达通知。

## 实施边界与接口对齐

依据：`contracts/api/openapi.yaml`、`docs/TARGET-ARCHITECTURE.md`、`docs/SECURITY-MODEL.md`、`docs/RELEASE-PUBLISHING.md`、`docs/SINGLE-NODE-OPS.md` 和项目任务设计。

现有接口可对齐的页面包括 `/me`、overview、catalog、events/query/exports、anomalies、entities/risks、cases、sources、collectors、quality、analysis/feedback/evaluation、releases、jobs、operations/status、audit、members/roles、平台发布者授权。

原型也覆盖目标能力。过滤策略发布、完整模型生命周期、完整备份恢复、自动建案策略编辑、保存查询和通知配置等入口，实施前需确认对应写接口、对象版本、权限和任务回执是否已具备。原型不代表这些后端能力已经上线。

正式实现优先顺序：通用布局与权限组件 → 调查闭环 → 来源/质量治理 → 分析/发布 → 平台运维。每个写流程至少对齐请求字段、权限、前置状态、乐观锁、幂等键、任务回执、失败恢复和审计。技术细节只在用户需要判断范围或恢复边界时展示。

## 验证

`verify.cjs` 使用 Playwright + 本机 Edge 验证。`verification.json` 记录 31 路由、32 标签视图、7 分步流程和 12 管理流程，无捕获的页面脚本错误。截图：`overview.png`、`investigation.png`、`mobile.png`。

这些验证覆盖原型渲染与流程提交；不验证实际授权、数据计算、真实接入和恢复能力。视觉已检查 1440px 桌面总览/调查详情与 390px 小屏布局。
